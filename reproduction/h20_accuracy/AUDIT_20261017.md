## 已修复的问题

1. `audit_inputs.py` 把权重文件直接当 tensor。实际作者保存 `OrderedDict`，runtime 读取 `['weight']`。原审计中断于 AttributeError。修复后完成 232 个文件的 shape、finite、softmax(dim=0) 列归一化、完整层编号及作者镜像 SHA256 比对。
2. `inference_conversation_batch.py` 不接受 Multi-News launcher 传入的 `--dataset`，导致 argparse 报错。增加显式类型参数，并保留旧命令的文件名推断；本机 CLI 验证通过。此脚本是已有复现仓库的补充实现，不是作者公开原文件。
3. `CudaIPCWrapper.to_tensor` 在冷启动进程先调用 `_new_shared_cuda`，后创建 CUDA tensor。实际跨进程测试复现 exit -11，失败点为 storage reconstruction；显式预先初始化 CUDA 后可通过。现把公开的 `torch.empty(..., device=...)` 放在私有 IPC storage 调用之前，以触发初始化。修复后冷启动测试通过 GPU 0→1、1→2、2→3、3→0 四组跨卡读写及非零 storage offset，目标运行时为 torch 2.10.0+cu128。这个修复是本地兼容性补丁，不是作者算法变更。

失败日志保留：`logs/audit_inputs.log`、`logs/cuda_ipc_diagnostic.log`。成功证据：`checks/inputs.json`、`checks/multinews_cli_help.txt`、`checks/cuda_ipc.json`。

## 数据与论文协议差异

按作者 loader 和 accuracy launcher 的过滤上限实际重新选样、套用 reasoning-off 模板并计数：

|任务|原始行数|选中评测项|实际 receiver prompt token 范围|没有完整共享 64-token block|
|---|---:|---:|---:|---:|
|HotpotQA|1,000|1,000|93–3,467|1|
|Conversation|100|1,014|84–10,188|29|
|Multi-News|5,622|1,000|104–4,857|0|
|RULER QA|100|100|17,249–20,445|0|

论文 Table 6 介绍 HotpotQA 4–8k、Conversation 12–20k、Multi-News 8–12k；发布 loader/data 的实际范围明显不同，不能把运行发布代码直接描述成严格匹配这些分布。

- Conversation 的 `num_max_examples` 只在外层 conversation 循环检查，内层 turn-window 展开会越过 1,000。按发布代码得到 1,014 是可复核行为；任何改为严格 1,000 的实验必须另记协议。
- 短样本没有共享完整 block，预期可能完全 fallback；不得通过混合平均分声称每条都发生了复用，也不能为提高 hit rate 删除这些样本。
- RULER launcher 指向不可用的作者机构绝对路径。bundled QA 文件长度接近 20k，可作为发布数据复现；尚不能证明与论文 Table 2 exact test file 逐项相同。用户已有的 KV-Lingo NIAH 数据不能冒充这个 QA 任务。
- 模型 tokenizer 的词表与 chat template 一致；每条 input/selected example 的哈希已保存到 `checks/*_selection.json`。

1. 发布脚本省略 temperature/seed。Qwen3 本地 generation_config 含 temperature=.6、top_p=.95、top_k=20；正式运行须记录 vLLM 实际生效参数，不能默认称作 greedy。baseline 和 MapFlow 必须使用相同请求协议。

3. 现有 evaluator 只输出非结构化日志，未充分记录逐题 input/response、错误、finish_reason 和版本化 resume。正式运行需要可审计结果与拒绝静默漏样本的门槛。
4. 权重是作者已发布 checkpoint，不是本机重新校准。公开代码未找到完整校准 trainer；MapFlow 的训练是 answer CE 的 end-to-end head mapping，不可用 KV-Lingo 的 KV least-squares 冒充。
5. 复用层为 receiver 3..N-2：8→1.7 有 24 层、14→8 有 32 层；末层权重文件虽存在，runtime 重算末层。RULER top-p 应分别 .92/.87，其他任务 .7。
